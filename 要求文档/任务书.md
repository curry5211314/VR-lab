# 任务书

## 基于肩关节动作训练的 VR 故事化交互体验设计

## 一、背景与任务

本课设提供六个基于 Unity 与 PICO 平台的肩关节动作交互项目。各项目已有动作相关目标生成、身体追踪、目标触发、计分反馈及数据记录等基础功能。你需要从六组动作中**任选一组**，根据提供的题目，**自由组合**选择目标用户年龄段和故事主题，在提供的工程基础上完成一套可体验的 VR 故事化交互作品。

选题采用“动作—目标年龄段—故事主题”的组合方式。作品应使用户理解自己的角色、任务目的、动作操作方式以及完成任务带来的变化，将重复动作组织为具有情境和进展的体验。

在实验中，你应能够：

1. **理解**已有 VR 工程的基本结构、输入方式与动作交互流程。
2. 根据目标用户的**特点**制定可解释的设计要求。
3. **建立故事任务与身体动作之间的对应关系**。
4. 在 Unity 中实现任务流程、场景变化及多种反馈，并部署到指定设备。
5. 根据测试中发现的问题进行修改，清楚表达设计依据、实现过程和作品局限。

自由组合你喜欢并且认为合适的主题，也可以自己设计主题。

可选年龄段：
        18-30岁  、 40岁以上

可选主题：

童话   森林   公园    科幻   机械   生活  太空   文化 …也可自主设计

**每个小组**：

**对每个小组安排两种动作，选择一个年龄段，为每种动作自选主题进行故事化设计，要适应你所选择的年龄段，比如小组A被分配到动作1和动作2，那么小组A可自选一个年龄段，自选2个主题，然后为动作1和动作2各完成一次你所选定的两个主题的故事化设计，也就是2x2**

至少要有完整的故事流程，将动作练习嵌入在故事情节当中

## 四、设计与功能要求

### 4.1 故事化设计

作品至少实现一段完整的“情境引入—动作任务—过程反馈—任务结果”流程，并满足：

- 用户能够理解自己扮演的角色及完成任务的要求。
- 所选动作是推进任务的核心操作，不能全部替换为普通按钮点击。
- 至少有一个故事状态随动作进度发生可观察的变化，如随着装置修复程度、环境恢复、角色回应或任务区域解锁等情况的不同而有不同的变化。
- 任务完成后呈现明确结果，并提供重新体验或退出入口。
- **扩展**：多次动作应具有可理解的目标和进展，不以增加重复次数作为唯一内容扩展。

**不要**仅替换模型、贴图、背景音乐或标题。

### 4.2 年龄段适配

1.提出至少三项具体的适配决策，并落实到课程设计中。例如文字大小与信息密度、指令表达、操作步骤、反馈方式、节奏、视觉风格等。

2.每项决策应说明“用户特点—设计选择—作品中的体现”。可结合资料、观察或访谈形成依据；应区分已获得的证据和待验证的假设。不要仅依据年龄标签自行提高动作幅度、速度或训练量。

### 4.3 功能需求

1. **进入与说明**：展示作品名称、目标及基本操作；必要时提示设备与校准准备。
2. **动作引导**：明确起始姿态、使用侧别、目标顺序和成功条件。
3. **任务交互**：保留所选动作的核心触发流程，能够连续完成一轮任务。
4. **过程反馈**：区分操作成功、当前进度和任务完成；反馈形式与故事一致。
5. **结果与退出**：提供完成反馈、重试或返回入口，避免用户进入无操作出口的状态。
6. **基础记录**：保留底包的数据记录与正常结束保存能力，不要求新增统计模型或研究分析。

引导不要仅依赖长段文字。应根据任务采用适当的视觉、声音或示范，并确保用户能辨认当前操作目标。

### 4.4 修改边界

| 类型 | 要求 |
| --- | --- |
| 可自主改造 | 场景、美术、角色、目标外观、音效、提示、任务组织、故事状态与奖励表现 |
| 必须保留 | 所选动作的核心交互、必要身体追踪、明确的开始与结束流程、基本数据记录 |
| 调整前需获得允许 | 对追踪接口或核心判定机制的实质改动 |
| 可选扩展 | 多任务分支、个性化提示、额外展示界面或其他不影响基本流程的功能 |

## 五、开发环境

### 5.1 统一环境

| 项目 | 要求 |
| --- | --- |
| Unity | `2022.3.62f1c1`，最好使用完全一致的版本，其实换个版本也无大碍，如果你已经有另一版本的编辑器，测试过兼容就没问题 |
| Android 开发模块 | Android Build Support、Android SDK & NDK Tools、OpenJDK；使用对应 Unity 安装的工具 |
| PICO 插件 | 保留工程内附带的 PICO Integration；包内声明版本 `3.1.2`，不按文件夹名称另行覆盖 |
| 渲染管线 | URP `14.0.12` |
| 构建平台 | Android，ARM64，IL2CPP |
| 入口场景 | `Assets/Standard main.unity` |
| Android API | Minimum 与 Target 均为 `29`，准备相应 SDK； |

具体详见 package.json

首次打开工程需要重新导入资源并解析包依赖，应预留时间与可用网络。

各组应设置独立应用包名，例如 `com.course.group01.qianqu`，并在应用名称中**标明组号**，避免共享设备上的作品相互替换或出现签名冲突。

### 5.2 已有功能检查

在做课设前，==一定要==先完成并记录所选基础项目的运行情况：工程打开、依赖导入、APK 打包安装、追踪校准、目标生成、触碰反馈、返回菜单和数据保存。

若在规定环境中存在问题，提交现象、日志及复现步骤，发给我确认。基础环境问题应尽早报告，**千万避免**ddl的时候才发现。==有问题及时向我反馈，我就在课程QQ群中。==

电脑端可用于场景、界面和故事逻辑开发；身体追踪、动作目标与碰撞效果应在指定设备上验证。Unity存在模拟器，但是模拟器上运行成功不能替代真机验收。
